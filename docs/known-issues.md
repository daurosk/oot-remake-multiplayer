# Known issues in the newest test release

This is an early test release. Everything under "Works" was seen in our two-game tests: two copies of the game on one PC talking through the server, driven by the [autotest](../tools/autotest) scripts, with the logs and screenshots of both games read afterwards. Testers play the releases on separate PCs, over a LAN and the internet. Please report what you see ([setup.md, Reporting a problem](setup.md#reporting-a-problem)); every open problem is on the [issues page](https://github.com/daurosk/oot-remake-multiplayer/issues).

**Every player needs the same release.** The release is protocol 10: a game and a server (or another game) of different protocol versions refuse each other, so every player updates (`Update.bat` in the kit folder, or answer **Y** when `Host.bat` / `Join.bat` offer it). Then run `make-puppet-pack.cmd` once more: `Update.bat` does not rebuild the pack, and the pack has new parts (the tunic colours, Epona for riders, the game-style HUD, Navi's room list). With an old pack the other players stay green; the kit warns at start when the pack has no colours.

**The emulator is Fritchii v5.8.4.** The first start after an update prepares the shaders again ("Preparing shaders"); let it finish.

## Works (seen in two-game tests)

- **Joining and leaving**: joining, leaving and rejoining after a crash (after a server restart, see Known issues). A join password turns away a wrong or missing password, and an address that keeps guessing wrong is shut out for a minute ([#160](https://github.com/daurosk/oot-remake-multiplayer/issues/160)).
- **Chat and names**: the chat box (Enter), the player list (hold Tab), name tags, and chat notices when someone joins or opens a chest. The old co-op panel with distance and ping is now for debugging only (F7).
- **Other players as Link**, child and adult ([#111](https://github.com/daurosk/oot-remake-multiplayer/issues/111)), following them live and copying their whole pose, with Navi beside them. A player who joins later gets a Link for everyone already there. A Deku Stick and a bottle show in their hand; the slingshot, bow and hookshot reach their Link too (seen in the logs, not yet on screen; [#92](https://github.com/daurosk/oot-remake-multiplayer/issues/92)).
- **Items**: key items, bottles, songs and one-time pickups are shared; small keys, Gold Skulltula tokens and heart pieces add up across players. Rupees, ammo and health stay per player. A shared Slingshot or bomb bag comes with its ammo ([#128](https://github.com/daurosk/oot-remake-multiplayer/issues/128)). A player who joins late gets the items found before.
- **Heart containers** raise every player's maximum health ([#88](https://github.com/daurosk/oot-remake-multiplayer/issues/88)).
- **Cutscenes and the Threads of Time**: the other Link hidden during your cutscene and held during theirs; the Threads of Time open for every player and its steps shared ([#193](https://github.com/daurosk/oot-remake-multiplayer/issues/193)).
- **PvP**, off unless the host sets `pvp = on` in `coop-options.ini` (or types `/pvp on`): sword hits hurt the other players, both ways (hits with items and shots not checked yet).
- **New in this release, seen in our tests**: no world reset when both players are in one area ([#159](https://github.com/daurosk/oot-remake-multiplayer/issues/159)); a rider on Epona ([#199](https://github.com/daurosk/oot-remake-multiplayer/issues/199)); another player's Navi stays in their own room ([#145](https://github.com/daurosk/oot-remake-multiplayer/issues/145)); the Deku Scrubs' 2-3-1 order split between players ([#149](https://github.com/daurosk/oot-remake-multiplayer/issues/149)).
- **Saves: the host's save decides.** When the host loads a save, every game goes back to that save's progress. A guest who joins from the title screen gets the host's save copied into a co-op save folder; press **Continue** to load it ([#167](https://github.com/daurosk/oot-remake-multiplayer/issues/167)).
- **Dungeons**: switches, doors and cleared rooms are shared, and a switch another player set stays set when you load your save ([#129](https://github.com/daurosk/oot-remake-multiplayer/issues/129)). A chest another player opens in your room disappears from your game.
- **Boss rooms**: when one player enters a boss room, the others are moved in and the intro starts together; a player who walks out during the fight is pulled back in.
- **Enemies**: their position, animation and life follow the player who owns them. All the Deku Babas of the Deku Tree's first room show in both games ([#132](https://github.com/daurosk/oot-remake-multiplayer/issues/132)). Townspeople and animals move the same in every game. The Stalchildren in Hyrule Field are shared too ([#124](https://github.com/daurosk/oot-remake-multiplayer/issues/124)).
- **Crates and thrown rocks** break in every game.
- **Things a player makes**: Deku seeds and arrows in flight and Deku Nuts appear in the other games, and seeds and arrows stay where they hit. A bomb another player holds stays in their hands with its fuse blinking, and it explodes on every screen at once, held or thrown.
- **`/teleport <name>`** moves you next to another player, in the same area or another one, except into a dungeon (see Known issues).
- **Kit**: `collect-logs` masks addresses and your PC and user name; the updater adds every new `coop-options.ini` setting below your own lines.
- **Mods**: texture and model mods work; a code or cheat mod stops co-op (see Other notes).

Co-op now looks for its places in the game's code by itself when it starts, so another build could work once someone checks it, but no other build is checked yet: a game it does not know is refused with a log line naming what differs ([#97](https://github.com/daurosk/oot-remake-multiplayer/issues/97), [game-builds.md](game-builds.md)).

- **After the host's server restarts**, a player can come back with another player number and see no other Link for a while. In our test the numbers of the two players swapped and neither saw the other's Link for the 30 seconds we watched; we do not know yet what brings them back ([#86](https://github.com/daurosk/oot-remake-multiplayer/issues/86)).
- **Ocarina and the other Link**: while a player plays the ocarina, the other Link is sometimes held still or hidden for a moment as if in a cutscene ([#86](https://github.com/daurosk/oot-remake-multiplayer/issues/86)).
- **Gold Skulltulas**: a kill reaches the other games, but picking up its token afterwards is not checked yet ([#89](https://github.com/daurosk/oot-remake-multiplayer/issues/89)).
- **Hookshot** (experimental) has its own list: see [Hookshot](#hookshot-experimental) below.
- **Shader stutter**: the first minutes and new areas stutter while the emulator builds shaders; it gets better as its cache fills ([FAQ](faq.md#the-game-stutters-what-can-i-do)).

## Hookshot (experimental)

- Test releases after this one are Hookshot only; this release still has the emulator kit.
- Co-op also runs on [Hookshot](https://github.com/NotRexed/Hookshot), a native PC build of the game that each player builds from their own game with the kit's `Build-Hookshot-Coop.bat` ([setup.md, Hookshot](setup.md#play-on-hookshot-experimental)). Hookshot and emulator players can play together.
- It needs Vulkan 1.3 with mesh shaders: NVIDIA RTX 20 or newer, AMD RX 6000 or newer; Intel is mostly untested.
- Checked on Hookshot in our tests: <!-- FILL from the integrator's Hookshot proofs 3-5 --> everything else is the same co-op code as on the emulator, not yet checked on Hookshot.
- **Other players may not appear on Hookshot yet**: in our two-game test on Hookshot both games connected, but the other player's Link was asked for and never shown. <!-- B #4: may change after Hookshot proofs 4-5 -->
- Not on Hookshot yet: the co-op window (panel, chat box and chat lines, player list, markers, the co-op HUD's hearts, the cheats window; so no chat commands); a Hookshot player's own ocarina notes are not sent, so others do not hear them ([#152](https://github.com/daurosk/oot-remake-multiplayer/issues/152)); tunic colours only partly: your own Link stays green, green players show as the plain puppet and `LICHII_COOP_TUNICS=0` is ignored ([#202](https://github.com/daurosk/oot-remake-multiplayer/issues/202)); no warning about an old puppet pack (a missing one is named); `collect-logs.cmd` does not pick up `hookshot_log.txt`; invite codes are not yet tested there.
- Hookshot itself is young: it can crash outside Kokiri Forest, lose the graphics device early on, or crash on some AMD cards (Hookshot's own issues). Use the emulator kit for longer sessions.

## AMD graphics cards

- AMD's driver crashed with the emulator's shader libraries (`amdvlk64.dll`; [#118](https://github.com/daurosk/oot-remake-multiplayer/issues/118)). The kit turns them off on a PC with an AMD card and no NVIDIA card. [setup.md, Troubleshooting](setup.md#troubleshooting) has the details.
- Without them, new places stutter longer the first time on AMD than on NVIDIA. The "Preparing shaders" step of the first start makes up for most of it (the kit has Fritchii's shader recipe): let it finish, also after a driver update. [setup.md, "Low frame rate"](setup.md#low-frame-rate) has more.

## Low frame rate

- Slow or uneven (for example under 20 fps): see [setup.md, "Low frame rate"](setup.md#low-frame-rate). In short: let "Preparing shaders" finish (after "Play now" it keeps running beside the game and slows it; close the emulator and start again to finish it); the first 10 to 15 minutes stutter while shaders are built; click the **60 FPS** button at the bottom of the emulator window to switch to 30 FPS; laptops plugged in and on the graphics card; a current graphics driver. The kit's emulator already uses the fastest settings.
- The co-op code reads the game at most every 33 ms, and its debug logging is off by default.

## Other notes

- **Mods**: co-op does not allow mods that change the game's code, or cheats ([#136](https://github.com/daurosk/oot-remake-multiplayer/issues/136)). `Host.bat`, `Join.bat` and `play.cmd` stop before anything starts when one is installed (a mod folder with an `exefs` or `cheats` folder, a loose `cheat_*` file, or code on the SD card) and name it. Mods turned off in the game's Add-Ons do not count, and neither does Dark's Dynamic FPS mod (Fritchii has it built in). Texture and model mods (a `romfs` folder only) are fine; every player should use the same model mods. If the emulator is started another way with a code mod, the panel says **"Co-op is off: a code mod is installed"** and co-op stays off until the emulator restarts.
- Windows may warn about the kit's programs the first time (unsigned): **More info**, then **Run anyway**. Windows Firewall may ask to allow `coop_server.exe` (on the host) and `lichii.exe`: allow them on Private networks (and Public for Hamachi or Radmin VPN, [play-online.md](play-online.md)).
- Hosting: `Host.bat` copies an invite code for friends over the internet ([play-online.md](play-online.md)); the server window also lists the address to give for each other case (VPN, port forwarding, same house). It asks api.ipify.org (HTTPS) for the internet address; `public_address_lookup = no` in `coop-options.ini` turns that off. If friends cannot connect, `check-hosting.cmd` checks the server and the firewall and prints the fix; it changes nothing itself.
- If an emulator is killed (not closed) and started again at once, joining takes a moment: the game asks again by itself for up to 12 seconds while the server lets the old one go.
- The kit's emulator is portable and never reads or writes `%APPDATA%\eden`.
