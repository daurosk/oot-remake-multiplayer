Offsets are into the loaded module (text 0x0, rodata 0x3c47000, data 0x484d000), read from `dump/main.plain` loaded as an NSO image. **Checked** means read from the instructions or the RomFS. Nothing on this page has been run yet.

## Same-scene filter and cutscene state (done)

`coop/host/include/coop/host/scene.hpp`, header only, tests in `tests/host/scene_test.cpp`:

- `same_scene(a, b)`: both scenes known, non-empty and equal. Unknown is never the same scene.
- `in_cutscene(flags)`: bit 2 of a `PLAYER_STATUS` flags byte.
- `visibility(local_scene, local_hides, remote_scene, remote_flags, remote_anim)` gives `hide`, `park`, `hold` or `show`:
  - other or unknown scene: `hide`;
  - our own cutscene running (`local_event_hides`: not while we play the Ocarina): `hide` (puppets are not actors the event knows, so they must not walk into its shot);
  - they ride a horse (`activity_of(remote_anim)`): `park` (puppet out of sight, marker kept);
  - their cutscene running, unless they play the Ocarina: `hold` (freeze at the last shown pose);
  - otherwise `show`.
  The cases this covers (title, menus, loading, Epona, Ocarina, crawlspace) are listed in [puppet.md](puppet.md#cases-issue-86).

The inputs already exist. The sender reads the scene (Banc +0x40, file name) and "event running" (event manager `*(main+0x4e94840)` +0x68 not zero, the game's `IsEventRunning` at 0xbcc100) in `coop/host` (`PlayerReader`, [host.md](host.md)) and sends the event bit as `PLAYER_STATUS` bit 2. The receiver keeps scene and status per player in `coop::presence::Presence` (`scene(n)`, `status(n)`, [presence.md](presence.md)). The local side is `PlayerReading::scene` and `PlayerReading::event_running` of this frame's reading.

One line each for the callers:

- Puppet (`coop_puppet.*`): `switch (coop::host::visibility(local.scene, local.event_running, presence.scene(n), presence.status(n)))`: `hide` despawns or hides the puppet, `hold` stops updating its transform and animation, `show` drives it as now.
- Overlay markers (`coop_window.*`): `if (coop::host::visibility(local.scene, local.event_running, presence.scene(n), presence.status(n)) == coop::host::Visibility::hide) continue;` (draw a held marker with its last pose).

## Shared story cutscenes (not yet run in a game)

Caleb's choice (2026-11-12): a story cutscene plays together for every player in the same room. Small talks stay in the talker's game; the NPCs in them move for the others through npc-anim (issue 200, [objects.md](objects.md) "Cutscene NPCs"). Code: `lichii/hook/coop_shared_scenes.{h,cpp}` (rules, tested in `tests/lichii/shared_scenes_test.cpp`) and `SharedScenes` in `coop_hook.cpp`. On with the live events; off with `LICHII_COOP_SHARED_CUTSCENES=0` (or `LICHII_COOP_LIVE_EVENTS=0`, which also turns this off).

- **Which events.** By event flow name (romfs `Event/EventFlow`, 215 names): every `Dm_` cutscene, plus `Meet_DekuTree`, `Meet_GreatFairy` and `Get_StoneOfFire/Forest/Water`. Left out: system flows (`Dm_SY_`, `Dm_MelodyGet`, `Dm_Title`, `Dm_StaffCredit`, `Dm_Ending`), the opening (`Dm_Kokiri_0000`, a new save in Link's house), parts played inside another cutscene (`_Effect`, `_Env`, `_Get`, `_move`), boss intros and outs ([dungeons-boss.md](dungeons-boss.md)), the Chamber of Sages (`Dm_Awake_`, `Dm_SageRoom_`), time travel (`Dm_TimeTemple_`, `DoorOfTime`, `Goto_`: threads-of-time, issue 193), every `Npc_` talk, and the room gimmick events ([dungeon.md](dungeon.md), "Live events"; no name is in both lists).
- **How it starts in the others' games.** The starter's game finds the cutscene's name in its event session on the event's 1st, 2nd, 4th, 8th and 16th frame (`CoopLiveEvents::FindRunningEvent` with the story names) and sends it as `DUNGEON_EVENT` (type 355, [protocol.md](protocol.md)): the server already relays it to the others in the sender's scene and keeps nothing, so no new message and no server change. Each other game asks its own game for the same event by name (the live-event requester, the AI node `SeqOneShotRequestEvent`'s calls). The start is as early as the network allows (one trip plus a frame or two), not frame-exact; each game then plays the cutscene on its own clock, so both end at about the same time. Puppets and Navi are hidden in our own cutscene (cutscene-hide) and eased after it (cutscene-snap, issue 194).
- **Who joins.** Only a player in the starter's scene, whose Link is within 30 m (`kRoomM`) of where the starter was last seen, and whose save has not played it (`HavePlayedEvent.<name>` not set). A cutscene joined starts at most once per visit of the scene; one our own game played is never asked again that visit, and one we only joined is not sent back.
- **Who cannot join.** Our own event running (a talk, another cutscene), the pause screen or a menu, or a load: the start waits up to 3 s (`kJoinUs`), then is skipped. Too far, another scene, played already, or the starter's place unknown: skipped at once. A skipped player gets the result by the shared flags and the quest catch-up (issue 173), as before.
- **Logs.** `coop: cutscene: our game started the story cutscene <name>: sent to the others in this scene`; `coop: cutscene: player N started the story cutscene <name> near us: playing it here too`; `coop: cutscene: player N's story cutscene <name> not played here (<why>); its result comes by the flags`; then the requester's `coop: dungeon: live event <name> asked of the game (result N)`.
- **Not known until a run.** Whether the event session holds a story cutscene's name (as for the gimmick events, not yet proven); whether a cutscene asked by name in a game whose own trigger did not fire plays right (its actors are in the room, since both players are); whether a flow with several entry points (`Meet_DekuTree`) starts at the same entry. If one misplays, `LICHII_COOP_SHARED_CUTSCENES=0` turns the sharing off.

### How the game changes scene

All checked in the RomFS graphs (`Sequence/*.ainb`, parsed node by node) and the flag list (`GameData/GameDataList.Product.110.byml.zs`, a big-endian BYML):

1. `Main.module` root runs `_LocalModule_cf31571495c4.module` (node 15), a native selector with eight cases: GameOver, ResetGimmick, MinusMenu, PlusMenu, Event, AssignableItemShortCut, **BancChange**, None. The BancChange case leads to `ChangeBancOnMain.module`. The `.ainb` of that local module is empty: the choice is made in C++. Its class name string is at 0x3d40b05, its name getter 0x33044e0, vtable from 0x4bd0158; slot +0xe0 (0xd59ee0) looks up the eight case names and stores the child indices at `this` +0x23 to +0x2a (BancChange at +0x28; the name 0x3db48e8 is loaded right before that store). The choice is slot +0x138, 0x3303ca0: see "Free-play scene change" below.
2. `ChangeBancOnMain.module` reads the String64 flag `Sequence_ReservedNextBanc` (hash 0xee27bf71), builds `Work/Banc/GameBancParam/<name>.game__banc__GameBancParam.gyml` and runs `ChangeBanc.module` with it. It also takes `OverrideTraverseStartPosName` from a GameData string. The event variant (`ChangeBancOnEvent.module`) also reads `Sequence_ReservedNextPosition` (Vector3 0x52046b85), `Sequence_ReservedNextStartPosName` (String64 0x0b570ab2), `Sequence_ReservedNextCancelSleepRot` (Vector3 0x1662143e), `Sequence_ReservedDungeonRoomID` (Int 0x050249d2), `Sequence_IsSameBancItemWarp` (Bool 0xdd257ad8). All six have save file index -1 (never saved).
3. During an event, `Event.module` takes the enum `Sequence_ControlInEvent` (0x8c1bbe2f; values Idle, ResetGimmick, BloodyMoon, **ChangeBancOnEvent**, MemoryShortageBloodyMoon, ResetAIScheduleNpc) to run `ChangeBancOnEvent.module`. This is the event flows' `EventReserveBancChange` path.

The String64 table, from its getter 0xcb0ea0 (called with 0xee27bf71 from 0x32998e0): `M` = `*(main+0x4e842a8)`, type 16, table at M + 0x610 (count), +0x618 entries (0x108 bytes each), +0x620 hash slots, +0x62c slot count; the string pointer is entry +0x68 and its capacity entry +0x70. A second table at M + 0x680 is searched when the hash is missing. Checked.

No code in `main` writes `Sequence_ReservedNextBanc` by its hash: the writers are graph nodes (`SeqOneShotSetNonStructGameDataString64` and the like) that hash the name at run time.

### The start point

A scene change must name a start point of the new scene: `Sequence_ReservedNextStartPosName` = a `StartPos` placement's name in that scene. Left alone, it keeps the start name of the scene the player came from (the name the game loaded the old scene with), which the new scene does not have. The scene then loads and runs (sounds, objects, 60 FPS) but the picture stays black. Seen in a test run: the host typed `/teleport B` in Kakariko, loaded `Graveyard_Child` with Kakariko's start name and stayed black (autotest runs host-save 20261111-003545 and teleport2 20261110-222949). Every autotest `warp` names a start and never went black.

So `/teleport` to another scene names the entrance start point of that scene nearest the other player (`CoopTeleport::NearestStart`), and refuses a scene it has no start point of. The table is `lichii/hook/coop_start_points.inc`, written from the game's scene files by `tools/puppet_pack/start_points.py` (`python -m puppet_pack.start_points --romfs <romfs> --out lichii/hook/coop_start_points.inc`, run from `tools`). It keeps the named start points a loading zone uses (the game puts an `EntrancePos*` placement at, or within 5 m of, each of them) and never keeps warp-song, cutscene, boss-rush, ending or mini-game starts, since those may start an event: a scene with only those (BossRushIntervalRoom, Demo_ShootingLocation_Tapestry_ED) has no row and is refused, as is SageRoom (one unnamed StartPos only). The game has 80 scenes in all (`Banc/BancBasedResource/StartPos.byml` lists them); Lake Hylia, Lon Lon Ranch and the Temple of Time are areas of HyruleField_Child/_Adult (their start names are there) and interiors are parts of their village's scene, so the table covers them.

### Free-play scene change (found 2026-11-11; the switch failed in game, the event path replaces it)

The selector's choice function 0x3303ca0 (vtable slot +0x138) checks, in order, the GameOver and ResetGimmick triggers, menus, the Event case and the item shortcut, and then, at 0x3304154, the **Bool flag 0x3fc35576** in the GameDataMgr (`*(main+0x4e842a8)`, the Bool table at +0x20/+0x2c, entry +0x16 value; then the BoolArray table at +0x80): if it is 1 it picks child +0x28, **BancChange**, which runs `ChangeBancOnMain.module`. That graph reads `Sequence_ReservedNextBanc`, loads `Work/Banc/GameBancParam/<it>.game__banc__GameBancParam.gyml` through `ChangeBanc.module` (the same module the event path runs: BeforeChangeBanc sets `Sequence_IsLoadingBanc`, unload, load, AfterChangeBanc) and sets a String64 (the request, emptied). It reads no start name or position: Link lands at the scene's own start.

- Flag 0x3fc35576: Bool, default false, reset type 0 (never reset by the game), save index -1. Its name is in no file of the game (main, every `.ainb`, every actor pack, Event, AI, Logic, Component, scanned with Murmur3 seed 0), and its hash is in `main` only at the two reads in 0x3303ca0, so **nothing in the shipped game sets it**: a leftover debug switch. A door or exit does not use it.
- What a loading zone does instead (read from the graphs and node names, not traced in C++): it is an event. The exit actors start an event (`FieldAndDungeonEntranceEventRequestActor`, `QueryBancChangeEventRequestArg`); the event flow's `EventReserveBancChange` sets `Sequence_ReservedNextBanc` / `NextStartPosName` / `NextPosition` and `Sequence_ControlInEvent = ChangeBancOnEvent`, and `EventToMain` / `ChangeBancOnEvent.module` change scene when the event ends. That is why the bare request was taken only during a talk.
- Run (integrate-p10-2, 2026-11-11, #156): the switch does nothing in free play. With the request and switch=1 set every 0.5 s, the game put the switch back to 0 within about 2 s, never loaded and no event ran, for 60 s. A real loading zone in the same run (probe): event=1, then banc/start/starter/boot set (`boot="Dm_SY_BancChangeArrive"`), control stays Idle, switch stays 0, the event ends, then loading=1. So the game loads a reserved scene when an event ends; the loading zone's event (`Dm_SY_BancChangeGo`, `EventReserveBancChange`) only fills the request.
- So /teleport now does what a loading zone does (`lichii/hook/coop_teleport_game.cpp`): `Sequence_ReservedNextStartPosName` = the start point above and `Sequence_ReservedNextBanc` = the scene (written straight into the table), then it starts the game event `DefaultParentEvent` (EntryPoint0 -> one `EventWait` on GameSystemActor: no actor, no picture, no talk) through the live-event requester (`CoopLiveEvents::Requester`, the node SeqOneShotRequestEvent's calls; [dungeon.md](dungeon.md)). The request is asked again every 0.5 s and the event again every 3 s (`Trip::kEventAgainUs`) while no event runs and nothing loads, until the game takes it (`Sequence_IsLoadingBanc` up, the scene unreadable, or the request emptied). On arrival the request is emptied; on give-up, leaving or a new /teleport the request is emptied and the start name read before the first ask is put back. The Bool 0x3fc35576 is no longer set (only cleared). A talk or sign that starts on its own takes the same request when it ends.
- Not set: `Sequence_ReservedBootEventName` and `...EventStarterName` (a loading zone sets `Dm_SY_BancChangeArrive` and the start name, so Link walks out of that entrance); without them Link appears at the start point. Proof: tools/autotest scenario `teleport-free` (docs/testing.md).

Probe: `LICHII_COOP_SCENE_PROBE=1` (`lichii/hook/coop_scene_probe.*`) logs a line `coop: scene probe: frame N scene=... event=... switch=... other=... loading=... control=... banc=... start=... starter=... boot=...` each time one of them changes. Walk through one door or exit with it on to see what a loading zone sets (expected: event=1, then banc/start set and control=ChangeBancOnEvent, then loading=1, switch=0 throughout); a free-play /teleport shows banc set, then event=1 (DefaultParentEvent), event=0 and loading=1, with switch=0 throughout.
