# Known issues in the newest release (0.11.7, the hotfix for 0.11.6)

This is an early test release. Everything under "Works" was seen in our two-game tests: two copies of the game on one PC talking through the server, driven by the [autotest](../tools/autotest) scripts or played by hand, with the logs and screenshots of both games read afterwards. Testers play the releases on separate PCs, over a LAN and the internet. Please report what you see ([setup.md, Reporting a problem](setup.md#reporting-a-problem)); every open problem is on the [issues page](https://github.com/daurosk/oot-remake-multiplayer/issues).

**Every player needs the same release.** 0.11.6 and 0.11.7 are protocol 15 and play together (0.11.6 still has the crash after about an hour that 0.11.7 fixes, tracker row 156: update); they refuse every older version at join, with the note to run `Update.bat`. 0.11.0 to 0.11.4 are protocol 12 and 0.11.5 is protocol 14: a game and a server (or another game) of different protocol versions refuse each other, so a 0.11.5 or older game cannot join a 0.11.6 game: update together. A 0.10.1 or newer kit offers the update when you start it. A kit from before 0.10.1 cannot: download `Update.bat` from the release page into the kit folder and double-click it. `Revert.bat` goes back to the version you had before.

**The game runs on Longshot v3.0.0** (Team MagicBean's recompilation; its changes are being merged into [Hookshot](https://git.notrexed.dev/Hookshot/Hookshot)). There is no emulator in this release: emulator players keep the last emulator release (the early test release of 2026-11-12 on the [releases page](https://github.com/daurosk/oot-remake-multiplayer/releases)), which cannot join a Longshot game. The first start builds the game from your own copy (10 to 45 minutes); later updates put the new co-op into it in a few minutes, or build it again when Longshot or our game patches move (0.11.6 builds it again, once, for Longshot v3.0.0). If Longshot's server cannot be reached, the build takes the same files from our [mirror](https://github.com/daurosk/oot-remake-multiplayer/releases/tag/longshot-mirror-v3.0.0), each checked by its SHA-256.

## Works (seen in two-game tests)

- **Hosting and joining in the game**: Host and Join in the **Multiplayer** tab (on the title screen press **−**), one invite code for the whole hosting session (**Join again** rejoins), **Leave**, joiners playing from the host's save, the self-updating start file, and **Same network or VPN** on the Host screen (one line with the address and the join password for friends in the same house or on a VPN, pasted into Join). Up to 16 players per session: tested with 2, more is experimental.
- **Joining and leaving**: joining, leaving and rejoining after a crash; invite codes between homes over the internet (players use them every day; Host asks the router for its port by UPnP). Game traffic is encrypted with the join password. A join password turns away a wrong or missing password, and an address that keeps guessing wrong is shut out for a minute ([#160](https://github.com/daurosk/oot-remake-multiplayer/issues/160)).
- **Chat and names**: the chat box (**T**, another key in Settings), the player list (hold **F6**), name tags, and chat notices when someone joins or opens a chest. The old co-op panel with distance and ping is for debugging only (F7).
- **Other players as Link**, child and adult ([#111](https://github.com/daurosk/oot-remake-multiplayer/issues/111)), following them live and copying their whole pose, with Navi beside them. New in 0.11.0: they move smoothly, on an even game-frame clock (the steady jitter and the choppy steps of 0.10.1 are gone; see Known issues for what is left). A player who joins later gets a Link for everyone already there. Their sword now shows in their hand (fixed for 0.11.0), and the slingshot no longer stays stuck out.
- **Customize Link** (new): the Multiplayer tab's **Customize Link** page gives the tunic and each part of the gear (shields, swords, boots, gauntlets) its own colour. Your own Link wears it when the menu closes, and the other players see it on your Link; it is saved for the next start ([puppet.md, The Link customizer](puppet.md#the-link-customizer)). The kit makes the puppet pack again by itself after this update (a few minutes, once).
- **Randomizer** (new): OOTRR is built in; turn it on in the Mods tab (**OoT Remake Randomizer**, **Settings**). In co-op the host's seed is everyone's: each guest's game builds it by itself ([mods.md, The randomizer](mods.md#the-randomizer)). A game with the randomizer on no longer stops while it loads.
- **Minimap**: the dungeon map no longer vanishes, and the other players show on it.
- **Time of day** (new on Longshot): the host's time of day is everyone's; a guest takes the host's time when the host's save loads ([#192](https://github.com/daurosk/oot-remake-multiplayer/issues/192), [time.md](time.md)).
- **Difficulty and helping up** (new): the difficulty follows the number of players or what the host sets, and a player at zero hearts can be helped up by another.
- **Items**: key items, bottles, songs and one-time pickups are shared; small keys, Gold Skulltula tokens and heart pieces add up across players. Rupees, ammo and health stay per player. A shared Slingshot or bomb bag comes with its ammo ([#128](https://github.com/daurosk/oot-remake-multiplayer/issues/128)). A player who joins late gets the items found before. Heart containers raise every player's maximum health ([#88](https://github.com/daurosk/oot-remake-multiplayer/issues/88)).
- **Cutscenes and the Threads of Time**: the other Link hidden during your cutscene and held during theirs; the Threads of Time open for every player and its steps shared ([#193](https://github.com/daurosk/oot-remake-multiplayer/issues/193)).
- **Saves: the host's save decides.** When the host loads a save, every game goes back to that save's progress. A guest who joins from the title screen gets the host's save copied into a co-op save folder; press **Continue** to load it yourself (the chat says when: "Host save loading, don't load a save.", then "Success, load any save.") ([#167](https://github.com/daurosk/oot-remake-multiplayer/issues/167)).
- **Dungeons**: switches, doors and cleared rooms are shared, and a switch another player set stays set when you load your save. A chest another player opens shows open in your game. In the Deku Tree (checked again on 0.11.4) the slingshot room's eye drops the ladder in every game ([#129](https://github.com/daurosk/oot-remake-multiplayer/issues/129)), the compass room's plate raises its platforms, and the torch and its web, and the water-level switch, work for everyone ([#176](https://github.com/daurosk/oot-remake-multiplayer/issues/176)). Dodongo's Cavern's looping lifts stay in step.
- **Boss rooms**: when one player enters a boss room, the others are moved in and the intro starts together; a player who walks out during the fight is pulled back in. Gohma's intro plays in every game, whoever starts it, and a player far away gets a chat line.
- **Down, not out** (new in 0.11.4): at zero hearts your Link goes down and crawls, with the shield; a teammate holds A beside you to help you up, child or adult. Not helped in time, you watch a teammate who is still standing, and you are back beside them once the fight is over. Enemies ignore a downed player.
- **Enemies pick the nearer player** (new in 0.11.4, [#150](https://github.com/daurosk/oot-remake-multiplayer/issues/150)), by the game's own rules, also when that player is in their own cutscene or away. Gohma no longer chases the host only. The aimed attacks of other bosses are another matter (see Known issues).
- **Signs** cut by one player are cut in every game, also for a player who comes in later ([#90](https://github.com/daurosk/oot-remake-multiplayer/issues/90)).
- **The ocarina**: the notes another player plays are played in your game, and their Link stays shown while they play. An ocarina another player gave you arrives and shows on your HUD ([#190](https://github.com/daurosk/oot-remake-multiplayer/issues/190)). (The rest of [#152](https://github.com/daurosk/oot-remake-multiplayer/issues/152) stays open until a player confirms they hear the songs.)
- **Epona**: a player riding her stays shown for the others ([#199](https://github.com/daurosk/oot-remake-multiplayer/issues/199); seen on the emulator, not yet on Longshot).
- **Held items on the other adult Link**: the Hookshot and the Megaton Hammer show in their hands.
- **Enemies**: their position, animation and life follow the player who owns them; the extra enemies for more players no longer stand on one spot. All the Deku Babas of the Deku Tree's first room show in both games ([#132](https://github.com/daurosk/oot-remake-multiplayer/issues/132)). Townspeople and animals move the same in every game. The Stalchildren in Hyrule Field are shared too ([#124](https://github.com/daurosk/oot-remake-multiplayer/issues/124)).
- **Crates and thrown rocks** break in every game.
- **Things a player makes**: Deku seeds and arrows in flight and Deku Nuts appear in the other games, and seeds and arrows stay where they hit. A bomb another player holds stays in their hands with its fuse blinking, and it explodes on every screen at once, held or thrown.
- **`/teleport <name>`** (or Teleport on a player in the pause menu's Multiplayer tab) moves you next to another player (fixed in 0.11.6, [#197](https://github.com/daurosk/oot-remake-multiplayer/issues/197)). If they are in another area, the game changes area at once by its own map change (no talk or sign any more) and puts you next to them; into a dungeon, next to them in any room. If the game cannot start it (you are in the air or in the water), the chat says so: stand on firm ground and type /teleport again.
- **Voice chat** (proximity, [voice.md](voice.md)) is off until you turn it on in the co-op settings; on, it is open mic, and the Voice mode row switches to push to talk (hold **V**). Off, your microphone is never opened. The Microphone row under it chooses which microphone (Default: Longshot's Insert menu's); there is no Speaker row: the voices play through the game's own sound output.
- **PvP**, off unless the host sets `pvp = on` in `coop-options.ini` (or types `/pvp on`): sword hits hurt the other players, both ways.
- **Kit**: `collect-logs` masks addresses and your PC and user name; the updater adds every new `coop-options.ini` setting below your own lines; `Revert.bat` goes back to the version before the last update; a `coop.ini` with a setting it does not know no longer turns co-op off.
- **Mods**: the Mods tab, and a note in the chat when your mods differ from the host's (see Other notes).
- **Gohma's intro** (fixed for 0.11.2): after it every player gets control back and the door closes for everyone.
- **Mods that sort before the co-op files** (fixed for 0.11.3): a randomizer seed from OOTRR's website, or another mod with its own game tables whose folder name sorts before the co-op files, no longer crashes the game 1 s into the start, and the other players show as usual.
- **Joining by address** (new in 0.11.2, from bmitch87's PR #230): IP address, Port and Password rows in Join, and a Port row when you host.
- **Chinese** (new in 0.11.2, from cirnoice9's PR #231): the co-op tabs in Simplified and Traditional Chinese when the game is set to Chinese.

## Known issues

- **Linux: away/paused state, Map page and HUD refresh** ([#150](https://github.com/daurosk/oot-remake-multiplayer/issues/150)): fixed in the code, not yet checked on Linux.
- **The title shows Continue only after a restart** after a new save (tracker row 124). 0.11.6 has the fix in the code (Continue shows right away after a new save or a save-folder switch), not yet checked in a game; if it still happens, start the game again.
- **Masks are not drawn on other players** ([#91](https://github.com/daurosk/oot-remake-multiplayer/issues/91)): the mask shows in the HUD slot but not on their Link. 0.11.6 has the fix in the code (the game's own armor-link draw byte, set where the game puts a mask on); our test could not put a mask on yet, so it is not yet checked in a game: tell us.
- **Bosses aim at the first player** ([#150](https://github.com/daurosk/oot-remake-multiplayer/issues/150), tracker rows 13 and 177): Phantom Ganon's light orbs and some other boss attacks go at the host's Link (or player 1), also when another player is nearer. Being designed for 0.11.8: the boss picks a different player at each attack.
- **A boss can get stuck in one move and can't be beaten**: seen with King Dodongo rolling in the middle of the arena (tracker row 149; the same in 0.11.4 and 0.11.5). 0.11.6 has the fix in the code (a boss stuck in one move chooses again; its parts follow their root's owner; a boss that is dying or in a cutscene is never made to choose, so its death plays out), not yet checked in a game: tell us if it still happens.
- **An invisible Lizalfos**: in Dodongo's Cavern one Lizalfos can be invisible on one player's screen. It is there and fights. 0.11.6 has a fix in the code (a mid-boss handed to another player while it appears now starts in their game too), not yet checked in a game ([#238](https://github.com/daurosk/oot-remake-multiplayer/issues/238)).
- **Host crash under heavy memory use**: a host crashed twice in Zora's Domain while the PC was nearly out of memory. Not fixed yet; `collect-logs` records memory use, so if it happens to you, attach its zip to `/bugreport` on the Discord ([#242](https://github.com/daurosk/oot-remake-multiplayer/issues/242)).
- **A click in the server window froze everyone's game world** for up to about 30 s, then a reconnect (it looked like an alt-tab freeze): Windows paused the host's server window (and the Join helper and relay windows) while text in it was selected. 0.11.6 turns that selecting off in those windows; not yet checked in a game ([#239](https://github.com/daurosk/oot-remake-multiplayer/issues/239)).
- **The graphics driver can reset**: rarely, an NVIDIA driver resets and the game closes with `VK_ERROR_DEVICE_LOST`. It is not caused by co-op (it happens in the game's own drawing); start the game again and rejoin.
- **Older AMD Radeon drivers can crash while shaders are prepared**: the "Preparing shaders" step (or one of the first starts) can stop with "the shaders were not prepared now (... exit status 3221226505)". The driver itself crashes compiling one of the game's own shaders; it is not caused by co-op, and Longshot skips that shader on the next start. Fix: update the AMD driver (Adrenalin), then start again (tracker row 154).
- **The last of the three Deku Scrub brothers waits for the talk** (the Deku Tree, room K): while one player talks to the brother they knocked back, that brother belongs to the talk in the talker's game, and the other players' copy of it waits until the talk ends. This is how the game's talk works, not a freeze; it moves again when the talk is over ([#243](https://github.com/daurosk/oot-remake-multiplayer/issues/243)).
- **Deku Tree's moving floor** (the water room; floating floors drift): the water-level switch is shared, but the floor can still move on its own in each game ([#196](https://github.com/daurosk/oot-remake-multiplayer/issues/196)). 0.11.6 has the fix in the code (a floor's phase lives in the game's own wave and rotate controller, which is now shared, protocol 15), not yet checked in a game.
- **A locked dungeon door another player opened** should open for you too. If it stays shut, type `/teleport <their name>` in the chat (inside a dungeon it takes you to them in any room), or step a few metres back from the door and come again ([#237](https://github.com/daurosk/oot-remake-multiplayer/issues/237)).
- **Customize Link, partly**: 0.11.6 paints the metal parts (shields, blades, gauntlets) so they take the colour you pick: seen on your own Link (the Hylian Shield's frame in its picked colour, no longer much darker); on the other players' screens not yet checked. Tell us if a part of your gear stays in the game's colours ([#202](https://github.com/daurosk/oot-remake-multiplayer/issues/202)).
- **Another player's sword without its blade**: with 5 or more players, or with the Giant's Knife or the broken knife, another player's sword can still show without its blade (fixed in the code since 0.11.4 and never seen working in a game: tell us).
- **Another player's ocarina is upside down** in their hand (fixed in the code since 0.11.4, never seen working in a game: tell us).
- **Shot impacts**: the shots of other players show, but the spark and bounce where they hit do not ([#166](https://github.com/daurosk/oot-remake-multiplayer/issues/166)).
- **DLSS is opt-in**: the kit builds Longshot without NVIDIA's DLSS kit, so only FSR is in the settings. An RTX owner can build it in on purpose with `NVIDIA DLSS.bat` (Linux: `bash start-squadala.sh --dlss`; [setup.md](setup.md#nvidia-dlss), PR #235 by StarAppeal, [#234](https://github.com/daurosk/oot-remake-multiplayer/issues/234)); not checked in a game.
- **Split screen is experimental**: it runs two full games on one PC with Nucleus Co-op, one per player (about 10 GB of RAM each and a strong graphics card; [play-lan.md](play-lan.md#split-screen-experimental)). The game that is not in front can be choppy ([#245](https://github.com/daurosk/oot-remake-multiplayer/issues/245)). Native split screen, one game for both ([local-coop.md](local-coop.md)), comes in a later release.
- **Linux kit (experimental)**: the Linux and Steam Deck kit (`Squadala-<version>-linux.zip`, [setup-linux.md](setup-linux.md)) has the same co-op; players host and join with it. Voice chat is not on Linux yet. Linux bugs carry the [linux label](https://github.com/daurosk/oot-remake-multiplayer/issues?q=is%3Aopen+label%3Alinux).
- **The randomizer**: if a guest's game cannot build the host's seed, that guest plays the base game, and the chat says so to everyone. 0.11.8 brings OOTRR 0.8.0 (0.11.5 to 0.11.7 had 0.7.3, 0.11.4 had 0.6.2): host and guests need the same release. 0.7 shuffles more (dungeon rewards, every progressive Bow, Bomb Bag and Slingshot, Darunia's Joy, Bolero, the Ocarina) and gives NPC, minigame, Great Fairy and song rewards with the normal item get, so the same seed word gives another world: start a new save for it. Shops are each player's own: a shelf that sells the next tier of an upgrade (0.7) sells it once in each player's game, so in co-op the group can buy that tier once per player. The update removes the older seeds and the game builds the seed again at its next start (about a minute, then restart). The Settings presets are default and keysanity. Do not install OOTRR by hand next to co-op: the kit's own is enough. A seed is built with the mods that are on at that time; turn other mods on or off before building. Since 0.7.1 a title-screen or menu mod of your own in `mods` stops the seed build (OOTRR names it): turn it off and build again.
- **Mods with a code patch (`exefs`), such as [OoT Character Select](https://github.com/snaildev99/OoT-Character-Select)**: Longshot v3.0.0 leaves a mod's code patches out (the mod's own menus show, its code does nothing; a character picked there stays Link for everyone). Building them in (Longshot's own #134, after v3.0.0) is planned for the next game build, with one fix of ours: Longshot v3.0.0 keeps a function's busiest registers in C locals and, before a call, writes back every one but x9 to x15, which the usual calling convention leaves free; Character Select's routines pass values in those (x11, x14 in, x12 out), so with its code built in, picking a character crashed the game. The functions a mod's code patch writes into keep every register in the context then.
- **Microsoft Defender** may warn about the zip or `Update.bat` ("Trojan:Script/Wacatac"): a false alarm on our scripts, which we report to Microsoft.

- **The pause menu's Multiplayer page and the title's Host and Join rows** (new in 0.11.6, DrHammer79, [PR #281](https://github.com/daurosk/oot-remake-multiplayer/pull/281) and the PRs after it): the page and the rows are drawn in both games and the game starts with them (0.11.5 made its pack without them because they crashed the game at start). Typing a room name on the Join rows, the list of games on this network, rejoining by itself and the page through a stall are in the code, not yet checked in a game. The Multiplayer tab opens as before (**−** and **+**, Home or F1).

## Longshot

- The game is [Longshot](https://git.magicbean.dev/MagicBeanDev/Longshot), a native PC version that the kit builds on your PC from your own game ([setup.md](setup.md)).
- It needs Vulkan 1.3 with mesh shaders: NVIDIA RTX 20 or newer, AMD RX 6000 or newer; Intel is mostly untested.
- Longshot is young: it can crash in some places or on some cards. Its own open problems are on [Longshot's issues page](https://git.magicbean.dev/MagicBeanDev/Longshot/issues). If it also crashes with co-op off ([setup.md, If something goes wrong](setup.md#if-something-goes-wrong)), it is Longshot's problem, not co-op's.
- On speakers, open-mic voice chat can send some of the others' voices back as an echo (there is no echo cancellation): use headphones or push to talk. Not yet tested with people talking: tell us how it sounds.

## Low frame rate

- Longshot builds its shaders the first time it sees each place, so the first minutes in a new place may stutter; it is smooth the next time ([setup.md, Low frame rate](setup.md#low-frame-rate)).
- The co-op code reads the game at most every 33 ms, and its debug logging is off by default.

## Other notes

- **Mods**: every game tells the others which mods it runs; when yours differ from the host's, the chat says so and the Mods tab lists what differs. You can still play, but a mod that changes the world (items, chests, enemies) can make your games disagree ([mods.md, Mods in co-op](mods.md#mods-in-co-op)).
- Windows may warn about the kit's programs the first time (unsigned): **More info**, then **Run anyway**. Windows Firewall may ask to allow `coop_server.exe` (on the host) and the game: allow them on Private networks (and Public for Hamachi or Radmin VPN, [play-online.md](play-online.md)).
- Hosting: **Host** in the Multiplayer tab copies an invite code for friends over the internet ([play-online.md](play-online.md)). It asks api.ipify.org (HTTPS) for the internet address; `public_address_lookup = no` in `coop-options.ini` turns that off. If friends cannot connect, try a VPN or port forwarding ([play-online.md](play-online.md)).
- **Your name and your invite code are private**: a new player gets a random name (like *Goron-4821*); change it in **Multiplayer**, **Settings**. An invite code holds your internet address and the join password: **share it in DMs only**, never in a public channel.
- If a game is killed (not closed) and started again at once, joining takes a moment: the game asks again by itself for up to 12 seconds while the server lets the old one go.
