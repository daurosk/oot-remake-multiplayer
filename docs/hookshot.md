# Co-op on Longshot (formerly Hookshot; Stage 2: recomp)

[Longshot](https://git.magicbean.dev/MagicBeanDev/Longshot) (Team MagicBean and contributors, GPL-3.0; https://longshot.magicbean.dev/) is the continuation of Hookshot (NotRexed and contributors; its GitHub page is gone since 2026-11-13), a static recompilation of the same game build co-op already supports: main build id `e0f3ccfaf50065ae` (version 1.1.1). The game's AArch64 code is translated to C ahead of time from the player's own dump, compiled for x86-64 Windows and Linux, with Horizon OS and NVN2 written natively and the GPU work replayed on Vulkan. No CPU or GPU emulation.

Co-op runs on it as Stage 2 (see [plan.md](plan.md)), experimental, next to the emulator kit in the release kits. This page is the design, for Longshot commit `0c74253d4c6ed08d57e4f3aa8ce8634c4c017085` (v3.0.0-rc.3, released 2026-11-13; before it v3.0.0-rc.2 `e7ed2f7a6526` and Hookshot `4aee23659b94`, v2.2.0-rc.1); the files are in `hookshot/` ([hookshot/README.md](../hookshot/README.md)); what is proven is under Status. Below, "Hookshot" means the same code base under either name.

### Longshot

Longshot's history holds Hookshot's (its tag v2.2.0-rc.1 is our old pin), so the move is a rebase forward. What changed for us:

- Names: the game is `longshot.exe` (in `bin\` of a builder's game folder), its log `longshot_log.txt`, its caches `longshot_*.bin`, its build switches `LONGSHOT_*` (was `HOOKSHOT_*`), its env header `gpu/vk/compat/longshot_env.h`. Ours keep their names: the `hookshot/` folder, `hookshot_coop.dll`, `Build-Hookshot-Coop.bat`, `tools/hookshot/hs.py`, the `hs-*` scenarios. `hookshot/PIN` says `runtime=Longshot`.
- Where it is: source and releases on Team MagicBean's Forgejo, `git.magicbean.dev/MagicBeanDev/Longshot`. The kit's builder (`scripts/hookshot-build.ps1`) takes the release's `tools.lock` (its SHA-256 in `tools/release/kit/hookshot/TOOLS.txt`) and fetches the windows-x64 tools it lists (llvm-mingw, Python, CPM, wgpu-native, third-party; not emsdk), each checked against its SHA-256, trying the listed mirrors in order; the source is Forgejo's archive of the pinned commit (`https://git.magicbean.dev/api/v1/repos/MagicBeanDev/Longshot/archive/<commit>.zip`, then the web `<repo>/archive/<commit>.zip`, which answers 404 since 2026-11-13; SHA-256 in TOOLS.txt). Nothing comes from github.com/NotRexed (gone since 2026-11-13): every tool has two git.magicbean.dev copies before tools.lock's GitHub fallback.
- Our patches: 0001-0004 and 0008 apply to v3.0.0-rc.3 unchanged in content (refreshed for hunk offsets only; rc.3's 12 commits remove the GUI/Python builders, which the kit does not use, and its tools.lock is the same file as rc.2's). On rc.2, 0001 and 0004 were refreshed for moved context lines only (a comment and an icon name in `host/posix/display_sdl.c` and `nx2/lift.py`, and line numbers in `host/nn_hid.c`). The bridge API (`host/hos_coop_api.h`) and the module are unchanged.
- Moving the pin: the newest Longshot release tag (`vX.Y.Z` or `vX.Y.Z-rc.N`, never a `nightly-N`): `hookshot/PIN` (commit, tag), `TOOLS.txt` (release, lock_sha256, source_commit, source_sha256), then `hookshot/fetch.ps1` and refresh the patches that need it.

Hookshot's own repository is never forked or committed to from here. Our repository gets only our patches, our code, docs and scripts. Built game files and Hookshot's generated C (both contain the game) are never published.

## Short answer

- Co-op fits Hookshot better than the emulator. The emulator cannot call a game function, so `lichii/hook` writes caves into main and talks to them through a custom SVC. Hookshot calls a game function from host C directly (`a64_lookup(address)(ctx)`), and adds C after any ordinary instruction at build time (`Lifter.after`; not after a call). The SVC cave, the hold cave and their assembly go away.
- Hookshot already does, for its own menu, much of what we need: a hook on Link's update (`hos_oot_is_player`), game function calls by address (`oot_teleport`, the GameDataMgr getters), the current map, cross-map teleports, and a local control socket for tests.
- Addresses: Hookshot loads main at **`0x80020000`** (Eden's layout: rtld at `0x80000000`, then main). Every offset in `CoopGameBuild::MainOffsets` becomes `0x80020000 + offset`. Checked on one function: our `set_time` `0x34522d0` is Hookshot's `0x834722d0` (`hos_main.c` `oot_set_time`). Data slots go through the same offsets; the first runs check them.
- Emulator and Hookshot players can join the same game: same game build, same coordinates and data, same protocol, same server. Nothing on the wire says which runs the game. (A Hookshot game shows the others as Link with our Hookshot patch 0002; see Status.)
- One copy of co-op for both: the module builds every `lichii/hook` file unchanged, with stand-ins for the emulator API they use (`hookshot/compat`). Our patches to Hookshot are small: the co-op bridge (`hookshot/patches/0001-coop-bridge.patch`) and the puppet guard (`0002-coop-puppets.patch`).

### Where the co-op module lives

Two parts:

1. **Our patch to Hookshot** (`hookshot/patches/0001-coop-bridge.patch`, for the commit in `hookshot/PIN`):
   - `nx2/coop_hooks.py`: the frame hook and the hold hook, each checked against the build id and the instruction words, else left out with a log line. Called from the lift (`nx2/lift.py`, two lines) next to `oot_occlusion.install`.
   - `host/coop_bridge.c`: on the first frame hook, loads `hookshot_coop.dll` from beside the exe (unless `HOS_COOP=0`) and hands it the C table in `host/hos_coop_api.h`: main's base and build id, the game folder, read, write, a 32-bit compare-and-swap, call (`a64_lookup` with the game's `Ctx` saved and put back whole, arguments in x0-x7, four stack words, s0) and the log. Without the DLL, both hooks return at once.
   - `host/nn_hid.c` (two lines): keeps player 1's buttons word as `GetNpadStates` gives it to the game (`hos_coop_pad`); the table's `pad_buttons` reads it, so your own Ocarina notes are sent as from the emulator's pad (issue 152). A module on a Hookshot built from an older patch still starts, without notes (its start line says so).
   - `host/nvn_native.c` (two lines): `nvnQueuePresentTexture` calls the bridge's `hos_coop_present`, which calls the module with `HOS_COOP_SITE_PRESENT` once it is loaded. The module runs `CoopHook::OnFrame` there, once per present, loads and pause included, as the emulator runs it at the guest's present; the callers' game calls stay at the every-frame site (they need the game's context). On a Hookshot from an older patch (no present calls) OnFrame stays at the every-frame site.
   - `gpu/vk/vk_coop.cpp`, `vk_coop.h`, `hos_coop_draw.h` and three lines in `vk_menu.cpp`: when the module (found by name once loaded) has chat lines or name tags to show, the menu's ImGui frame is made and they are drawn under the menu. A module with `hos_coop_draw2` gets the whole table: the HUD pack's fonts (ImGui `AddFontFromFileTTF`, any time with ImGui 1.92) and pictures (`ImTextureData` + `RegisterUserTexture`, copied in on the present's command buffer as the logo) are loaded once and kept.
   - `host/display.c` (two cases) and `host/nn_hid.c` (one line): key presses and characters go to the module first (`hos_coop_key`, `hos_coop_char`); while `hos_coop_keys_taken` says so, the game reads no keys, as while Hookshot's own menu is open. Also the mouse: `display.c` offers the cursor (a fraction of the client area: `hos_coop_mouse`) on a move, a left click and the wheel while no menu has the mouse, and lets a captured mouse go when a key opened the chat box or the panel.
   - No `nx2/build.py` change: it compiles every `host/*.c` and `gpu/vk/*.cpp`.
2. **The co-op module** (`hookshot_coop.dll`, CMake target `hookshot_coop`, built with MSVC as the emulator's hook is): **all of `lichii/hook`**, the files `lichii/hook/core.cmake` lists, except the emulator's cave (`coop_svc.cpp`); `coop_testinput.cpp` is built without its pad input and plays the autotest driver's test commands (place, give, assign, chat, setflag, setenum, wear, kill) from the file `LICHII_COOP_TEST_COMMANDS` names. `hookshot/compat/` stands in for the slice of the emulator's API those files use (`Core::System`'s memory, process and build id, the loader's module list, `Common::FS` folders, `LOG_*`), answered from the bridge's table. So every co-op feature of a release is in both builds from one copy of the code, and a hook file that reaches for more of the emulator fails the module's CI build. `hookshot/src/coop_hookshot.cpp` drives it: `CoopHook::Start`, `CoopHook::OnFrame` at the every-frame site, then the callers' game calls (`lichii/hook/coop_callers.{h,cpp}`, the same stepper the emulator's `svc #0xf4` handler asks), the AI hold (from a table in the module's own memory, `CoopHold::HostTable`, which the Objects step publishes; the emulator's hold cave reads the guest table), `CoopHook::Shutdown` at exit.

3. **Actor events** (patch `0007-coop-actor-events.patch`, after 0005's world hook layer; native-plan rows 7-10): `nx2/coop_actor_lift.py` puts C after one instruction in four game functions and hands each call to the module through `host/coop_world.c` (`hos_coop_world`; the numbers are in `hookshot/src/hos_coop_actors.h`): the create request `requestCreateActorAsync` (main+0x372a94: caller, create argument, name, handle slot), the delete request where it is accepted (main+0xa65d0, once for an actor: actor, reason; the Sync then counts the actor gone at the first walk without it, not the second) and the Life component's step (main+0x49dcb0: component and this frame's damage sum, which the module may change: another player's hit goes in through the game's own step, `CoopActorEvents::LifeTable`). The create hook also asks the module whether to stop the request (`HOS_COOP_WORLD_CREATE_STOP`): a copy enemy's own shot (`CoopEnemyShots::StopAtCreate`, the same rule as the walk's: the nearest maker belongs to another player) leaves through the game's own "the manager takes no creates now" exit, so it is never made here and only the owner's shot is seen, as a copy (`LICHII_COOP_ENEMY_SHOTS_STOP=0` turns that off; the walk then deletes it as on the emulator). What the game asks inside one of the module's own calls (a copy made, a remove) is marked as ours and never stopped. Words and build id are checked; the fourth is the game's shoot code (main+0xc16d24, `HOS_COOP_WORLD_SHOOT_FROM`: the shooter's actor, so a copy enemy's shot is known by who fires it and not by where it appears); the build log says `co-op actors: 4 of 4 actor event hooks`. The module pushes them into a lock-free ring in its own memory (`lichii/hook/coop_actor_events.h`) and the Objects step drains it on the frame hook. A hit of this game's on another game's enemy is taken from that step (`Sync::GameHit`), not from the life read falling: the fall is only paired with it (either may be seen first), a fall while the owner's hurt is in flight is that hurt, and a fall that no step explains within 0.3 s still counts and is logged (`coop: actors: N life fell on copies with no Life step for it`). On Hookshot the module never writes the game's damage field (the step would report it back as a hit): a life change goes through the step, or is written when the step does not take it in 0.25 s (the step skips its sum on two paths: bits 3 and 12 of Life+0x1d18 set, or no life value at Life+0x1c10; the log names the actor: `its Life step did not take the change`). The table of given hits is emptied on every new scene.

A DLL keeps the patch to Hookshot small (it changes only when Hookshot moves) and keeps our C++20 out of Hookshot's C build.

### Hosting from the game (in progress)

A player hosts without the separate server window: the module runs the co-op server on a thread of its own. `server/host_service.hpp` (`HostService`) is coop_server's hosting loop as an object: the game server and, when the host asked, the router forward (UPnP), the relay and the invite code with its answer codes. `coop_server` itself is a loop around the same object, so a dedicated host keeps the standalone server and its window says the same lines. Every session has a join password (a new random one when the host gives none) and encrypted traffic; the router forward opens only when the host said yes. Status for the menu (`HostService::status`): the port, the players, the invite code or why there is none, the last problem in plain English. The Multiplayer tab (below) calls it.

## World hooks

Co-op takes part in the game's world through the game's own functions instead of caves and guest memory. One layer does it, our patch 0005 (`hookshot/patches/0005-coop-world-hooks.patch`, header `hookshot/src/hos_coop_world.h`, Hookshot's `host/coop_world.c`), made when Hookshot is built:

- **Events after one instruction** (`Lifter.after`): `hos_coop_world_event(event, a, b)` reaches the module's optional export `hos_coop_world`. The AI pause counter start (main+`0x5e6778`, `nx2/coop_platform_lift.py`) is `HOS_COOP_WORLD_COUNTER_START`: the node goes into a ring in the module's own memory (`CoopCounters::HostRing`), which the Objects walk reads as it read the guest ring. No game malloc, nothing at main+`0x3c46780`. The emulator keeps its cave.
- **Wrapped game functions** (`Lifter.wraps`, in `third_party/a64-kit/lift/a64_lift.py`, and sent to the emit workers through `nx2/chunks.py`'s `EMIT_TABLES`): every call of a listed function, and the indirect table, reach `hos_coop_w_<entry>` in `a64_hooks.c`, which calls the module's optional export `hos_coop_wrap(id, phase, x, ctx)` before (phase 0; 1 = the module did the call's work) and after (phase 1) the game's own unchanged `f_<entry>`. `nx2/coop_world_wraps.py` lists them with their first words; build id and words are checked, and a function Hookshot hooks or edits by name is never wrapped. First wrap: the flag applier (main+`0xb99980`, `HOS_COOP_WRAP_FLAG_APPLY`), which only counts for now (`coop: world wraps: the game's flag applier ran N times`).

Hookshot keeps the exports only once the module answers `HOS_COOP_WORLD_HELLO` with 1, so a module the bridge refused is never called. The hello carries the hook level (`HOS_COOP_WORLD_VERSION`) and the wraps that build has, a bit for each id; the module logs both, and says so when Hookshot was built with an older patch. Only a function the lift really made is wrapped (not a PLT stub, not one that calls setjmp); the lift prints what it left out. Flags are on this layer: the applier's wrap gives the flag watcher the game's own writes as events, and co-op's writes go through the game's setters on its calc thread ([flags.md](flags.md), "Through the game's own functions"). Time of day is too: the wrap of the game's one time function (main+0xeee640) makes the game's own set the jump the others take ([time.md](time.md), "Through the game's own function"). So are event starts: the wrap of the game's event request (main+0xd7a820) names the event our game started at the request, for a dungeon room's events and the story cutscenes; the search of the event session stays as the emulator's way and as a net that logs any start no request named (`coop: dungeon:` / `coop: cutscene: an event start found by the search that no request of the game named`). A function Hookshot's own edits change at its head can be wrapped (the wrap leaves the function's text alone); one whose calls those edits look for by name cannot.

Teleport to another scene has the game's own way behind a switch, `LICHII_COOP_TELEPORT_EVENT=1` (off until a run has shown it): the event `Dm_SY_BancChangeGo` with the arguments `NextBanc`, `NextStartPos`, `BootEventName` (`Dm_SY_BancChangeArrive`) and `IsCheckAir`, started by our Link, as an entrance asks it (the layout of an event's arguments is in `lichii/hook/coop_live_events.h`; Hookshot's own teleport asks the same event). The event calls the game's `ReserveBancChange` and the map loads when it ends, so nothing of co-op is written into the request flags (today: two String64 flags written straight into their buffers, then a plain event to make the game take them). To check in a run with the switch on: `/teleport <player>` to a player in another scene logs `coop: teleport: asking the game's map change event Dm_SY_BancChangeGo for <scene> at <start>`, the map changes once, and Link stands at the other player. Not known yet: whether an entrance's own arrival event (a few scenes have one, such as `Dm_SY_BancChangeArrive_KakarikoVillage_01`) is needed there.

## For players: the kit

Nothing of Hookshot or the game is in the kit. The Hookshot-only kit (`tools/release/make_kit_hookshot.ps1`, player steps in [setup.md](setup.md)) has one entry point, `Start OoT Co-op.bat` (`scripts/start.ps1`): it checks the kit first (`scripts/start-checks.ps1`: still in the zip, a double start, OneDrive or a path the build cannot use, no write rights, files an antivirus took, the Visual C++ runtime, other kits on the PC), then runs `play.ps1 choose -Hookshot` (update, build or bring the game up to date, start with co-op idle; Host and Join in the game). It ships no emulator, Fritchii or Lichii file, and the updater turns an emulator kit into it (the emulator files go to the backup, `emulator\user` stays). The build step, `scripts/hookshot-build.ps1` (`Build-Hookshot-Coop.bat` in the emulator kits, [setup-emulator.md](setup-emulator.md#play-on-hookshot-experimental)), downloads Hookshot's builder parts and source for `hookshot/PIN` (each checked against its SHA-256), applies `hookshot/patches` without git, runs Hookshot's own `nx2/make_game.py` on the player's game file, and installs `hookshot_coop.dll`, `coop.ini` (beside `hookshot.exe`) and the puppet pack. `Host-Hookshot.bat` and `Join-Hookshot.bat` start it as `Host.bat` and `Join.bat` start the emulator.

**Linux and Steam Deck** ([setup-linux.md](setup-linux.md)): `tools/release/make_kit_linux.sh` makes the Linux zip in the same layout (one `start-oot-coop.sh`, `README.txt`, `scripts/`, and `data/` for the rest). Its `scripts/build.sh` takes Longshot's own Linux builder for the pinned release (`hookshot/LINUX.txt`: the release's AppImage, SHA-256 checked, unpacked without FUSE), applies `hookshot/patches` to a copy of its source, fetches Longshot's Linux tools with Longshot's `builder/linux/linux_tools.py`, and runs `nx2/make_game.py` without `LONGSHOT_TOOLS` and without the prebuilt renderer: the game is `data/game/longshot` in one folder (no `bin/`), with `hookshot_coop.so` (the same CMake target, built on Linux), `coop.ini` and `mods/` beside it, and the renderer compiled from the patched source. The module's `FindKit` takes `data/` as the kit on Linux (`server/coop_server` and `coop-options.ini`), and its clipboard goes through `wl-copy` / `xclip` / `xsel` (`hookshot/src/coop_clipboard_posix.cpp`). CI's `linux-longshot` job builds the module and server on Ubuntu 22.04, loads the module as the game does (`tests/hookshot/load_module.c`), makes the zip and runs the kit's build without a game up to the patched renderer.

What the module expects from that install (`hookshot/compat`): `coop.ini` beside `hookshot.exe`; the puppet pack at `<exe folder>\mods\contents\0400486024DEC000\coop-puppet` (the hook finds packs under `<load folder>\0400486024DEC000\<mod>`, and Hookshot's `host/mods.c` loads that layout as a mod); the `LICHII_COOP_*` switches from `coop-options.ini` in the environment.

## The Multiplayer tab

Hookshot only (patch `0012-coop-menu-tabs.patch`, with `0004-coop-title-menu.patch` for the title's rows): co-op lives in Hookshot's own pause menu, so nobody edits files or runs a .bat to play together. Open the menu with **F1** (or Insert, Esc by default) or a pad's **Home** (or Select and Start together); **Multiplayer** is its first tab, before Graphics. Its pages: **Host a game**, **Join a game**, **Local co-op**, **Settings** and **Commands**. The **Lobby** tab follows it (below), then a **Mods** tab, through the same table, with no further Hookshot build.

- **How it is drawn.** Patch 0012 changes only Hookshot's Vulkan back end (`gpu/vk`: no game rebuild). `hos_coop_menu.h` is the table (the same file in `hookshot/src`, checked by `tests/hookshot/module_test.cpp`): the module names its tabs (`hos_coop_menu_tabs`, `hos_coop_menu_tab_name`), gives a tab's rows, the selected one, the help box and the prompts' words (`hos_coop_menu_page`), and takes the presses (`hos_coop_menu_input`: Up, Down, Left, Right, Confirm, Back, the tab shown or gone, the mouse over a row and its clicks); `hos_coop_menu_wanted` opens the menu on a tab or closes it. `vk_coop.cpp` finds the exports once the module is loaded; `vk_menu.cpp` puts the tabs first in its strip, draws a module tab with its own cells (an action, a choice with arrows, Off / On halves, a heading, a note) and help box, and hands the presses on. A Hookshot without the patch shows no tab; a module without the exports, none either. The tab's logic is `coop_pause_menu.cpp` (tests in `tests/hookshot/pause_menu_test.cpp`); `coop_pause.cpp` carries out what it asks.
- **A picture beside a page (patch 0019).** `hos_coop_menu_picture.h` (the same file in `hookshot/src`, checked by `module_test.cpp`): an optional export, `hos_coop_menu_picture`, asked right after `hos_coop_menu_page`, hands the menu coloured convex shapes (3 to 8 points each, in a unit square, filled or outlined); `vk_menu.cpp` draws them in a square over the top of the help column and the help box under it. Vulkan back end only, no game rebuild; a module without the export: no picture. The Customize page draws Link with it ([puppet.md](puppet.md#the-link-customizer)). As a generic call it could become part of a mod API later.
- **Controls.** Pad: D-pad to choose and change, A to open or do, B back (on the first page B closes the menu), L and R the tabs. Keyboard: the arrows, Enter, Esc, Q and E (or Tab) the tabs; the mouse: a row under the cursor is chosen, a click does it (a value's left or right half changes it), a right click goes back. While a field takes typing (your name, a friend's code) the keyboard types into it (Q, E and Tab type too), Backspace erases, Ctrl+V pastes, Enter is done and Esc cancels; F1 still closes the menu. Hookshot has no software keyboard (swkbd): text comes from the keyboard or the clipboard (A on an empty code field pastes it, so a pad player copies the code and presses A).
- **Host a game** is one press: the co-op server starts inside the game (native-host-b, `hos_coop_host.h`: a new random join password inside the invite code, UPnP, up to the settings' player count), this game joins it, and the invite code goes on the clipboard by itself. The page then shows the code, how many joined, **Copy the code again**, **Paste friend's answer** (when a friend's router blocks the way in), **Same network or VPN** (one line with this PC's address and port and the join password, `192.168.1.20:27510 password`, a VPN address first, for friends in the same house or on Radmin VPN, Hamachi or Tailscale; Join's field takes that line as it is) and **Stop hosting** (two presses).
- **Join a game**: **Join *name* again** first when this game joined before (the last code, one press), then **Friend's code** (A pastes the clipboard, or type it) and **Join**. When the host's router blocks the way in the page offers **Copy your answer code** for the host to paste. Once connected the page shows **Leave the game** (two presses). A join at the title closes the menu and the host's save loads in one step (the title's Continue pressed for the player, `CoopTitleMenu::AutoLoad`); a join during play keeps the game as it is, and the host's save loads the next time the title is up.
- **Local co-op**: split screen comes in a later test release; the page says so, and its help points to Host and Join between two PCs meanwhile.
- **Settings**: your name (the Windows user name until you change it), **Link's look** (the tunic colour, by player number or one of the list; worn when the menu closes, through `coop_look.h`: `ChooseLook` and `WearChosenLook` in `coop_pause.cpp` are the only places it is wired), **Players when you host** (2 to 16) and **Proximity voice chat** (Off by default; On writes `LICHII_COOP_VOICE=ptt` in the kit's `coop-options.ini`, Off removes the line, an `open` written by hand stays open, also for the run Host or Join start; voip-101's `CoopVoice` reads it). **Chat key** (T, Y, U, C, F2, F3, F4 or Off; `LICHII_COOP_CHAT_KEY`, counts at once through `CoopHookshot::SetChatKey`). **Controller** and **Keyboard and mouse** (only with patch 0015: `coop_input.h`, pad-select's rows; all / one pad / none, and window in front / also in background / off; each press goes to the next choice, counts at once and is saved as `LICHII_COOP_PAD` / `LICHII_COOP_KEYBOARD` in `coop-options.ini`). Each change is saved at once. The other settings stay as they are in `coop.ini` and `coop-options.ini`.
- **Commands**: the key that opens the chat (T by default; its help says to change it in Settings, Chat key) and every chat command with what it does (`/teleport`, `/teleport <player>`, `/tp`, `/pvp`, `/pvp on|off`, `/kick`, `/ban`, `/mute`, `/unmute`), read only. The list is `CoopPauseMenu::Commands()` in `coop_pause_menu.cpp`: a new chat command adds its line there.
- **Co-op started with the game** (`Host.bat`, `Join.bat`, a server in `coop.ini`): the tab shows "Co-op is on" and leaves Host and Join alone; Settings still works. With no server in `coop.ini` the module stays loaded with co-op idle (patch 0004's Hookshot and later, or `HOS_COOP_MENU=1`) until Host or Join on the tab. Started without the launcher, the module reads the kit's `coop-options.ini` switches itself (the kit is found from `OOT_COOP_KIT`, `coop-kit.txt` beside `hookshot.exe`, or the folders above the game). `LICHII_COOP_TITLE_MENU=0` keeps the module off when coop.ini names no server.
- **The title screen** is the game's own: no co-op rows and no prompt (the owner's call: the title looks like the plain game). Minus at the title still opens the menu on the Multiplayer tab, and the host's save loading after a join says "Loading *name*'s save..." at the bottom left. The kit's pack step no longer passes `--title-rows`; what follows is how those rows worked, kept for a later use (the module still sets them up when a pack has them). With `--title-rows` the title's list has three more rows under Continue, New Game and Options: **Host**, **Join** and **Co-op Settings**, the game's own title buttons (its `PaCommonBtnTitle_00` part, highlight bar, ornaments, move and press sounds), with texts from the game's own message files. The puppet pack makes them from the player's game (`tools/puppet_pack/title_menu.py`): `Title_00.buil` gets three more button parts `Pa_Button_04..06` under the title's alignment pane (Layout2: appended after the string pool, no existing offset moves; every copy of the layout in the archive), and `LayoutMsg/Title_00.msbt` gets labels 0100-0102 in every language; the size table grows with them. The title's own code makes a button for each part it finds; at its set-up the module sets the three texts the way the game sets its own (`f_80a86f70`, `f_80a8afe0`, `f_80a87d30` with the message ref in the call's scratch). A press on one opens Hookshot's menu on the Multiplayer tab at that page (Host hosts at once; Join has a code already copied pasted).
- **How it is found in the game**: the title is a `UITitleScreen` (vtable 0x84c106e8, built by main+0x3406710; +0x2c8 its button count, +0x2d0 its buttons, +0x2e0 the focused one, +0x1a8 1 while it runs). Its layout `Title_00` (romfs `UI/Layout2Archive/Title...blarc`) has four button slots `Pa_Button_00..03`; the game shows three (New Game, Continue, Options: `LayoutMsg/Title_00` 0000-0002), set and counted by the Sequence graph `OpenTitle.module.ainb` (text per button, the `BtnNum` animation's frame), and what a press does is `NormalTitle.module.ainb`'s, not C++. Patch 0004's `nx2/coop_title_hooks.py` calls `hos_coop_title` from three places in that screen (set-up done, its active step, its destructor); `nn_hid.c` hands player 1's pad to `hos_coop_pad` first; the API's `scratch` and an x8 for `call()` let the module call the game's message functions for the rows' texts. Hookshot has no software keyboard (swkbd), so text comes from the keyboard or the clipboard.
- **The 4th title button**: the game keeps its fourth slot `Pa_Button_03` hidden (the `BtnNum` animation's frame); `LICHII_COOP_TITLE_NATIVE=1` makes A on it open the Multiplayer tab too, for tests. The new rows are not in `BtnNum` (its tracks name panes in a packed form not read yet), so they always show.

## The Lobby tab

The second tab, after Multiplayer (module only: patch 0012's table, no Hookshot or game build). The players of the game you are in, the invite code with Copy, the host's game, and on each player the mutes, Teleport to them and the host's Mute for everyone, Kick and Ban (play-online.md, "Lobby"; protocol.md, "Lobby"). Its logic is `coop_lobby_tab.cpp` (tests in `tests/hookshot/lobby_tab_test.cpp`); `coop_lobby_tab_module.cpp` fills it from the hook's `CoopLobby::Now()` (lichii/hook `coop_lobby_game.cpp`: the room, the host's mutes, the downed players), `CoopHook::PlayerList()` (ping, scene), the voices and the hearts, and sends what it asks for; the server (`server/session.cpp` `on_lobby`) does every host action. Out of a game it says to host or join on the Multiplayer tab. Mods is the third tab.

## Size

- Our patch to Hookshot: `coop_hooks.py` 70 lines, `coop_bridge.c` 150, `hos_coop_api.h` 50, `lift.py` 2.
- Ours: `hookshot/src` about 250 lines, `hookshot/compat` about 250, `coop_callers` 100, the kit script 120 and the patch applier 90. No hook file changed for Hookshot except `coop_svc` (its stepper moved to `coop_callers`).
- Building Hookshot: the game unpacked (~26 GB), ~1.4 GB of generated C, 25 to 60 minutes the first time.

## Risks

- **Memory.** A Hookshot game takes about 10 GB of RAM; 8 GB of VRAM is recommended. Two games on one PC are fine on the test PC (128 GB of RAM) at the normal preset; players with 16 to 32 GB of RAM should run one game each.
- **Open crashes and GPU limits.** Hookshot needs Vulkan 1.3 with mesh shaders (RTX 20 or newer, RX 6000 or newer); Intel is mostly untested. Open issues there: an intermittent device loss after the first gameplay frames (its design.md, S4), crashes outside Kokiri Forest (Hookshot issues 317, 648), AMD crashes (708, 614).
- **Patch upkeep.** Hookshot moves fast. Our patch touches three new files and two lines of `nx2/lift.py`; moving `hookshot/PIN` (and the kit's list of builder parts with it) is a test like moving the Fritchii pin.
  - **The move to v2.2.0-rc.1** (from c544828, 66 commits). Every hunk of the three patches applied unchanged except one: `host/hos_sdl.c` merged by hand, because Hookshot added its own optional SDL functions on the lines beside our `StartTextInput`. The upstream changes to the files we touch were these: `vk_menu.cpp`'s `menu_record` gained the frame-generation menu, with the same three conditions; `nn_hid.c` gained the stick's dead-zone pairs and `player_used`; `nvn_native.c` and `nx2/build.py` changed only by moving lines. `nx2/lift.py`, `display.c`, `display_sdl.c` and the hook sites did not change. Hookshot's lift now writes the C in several processes on Windows too (its #2748). Our hooks still reach every process, because all three (`coop_hooks.py`, `coop_puppet_guard.py`, `coop_platform_lift.py`) write only `Lifter.after`, which is one of the tables sent to each process (`EMIT_TABLES` in `nx2/chunks.py`). Hookshot's new game patches (the new-game opening, its own zstd) are in other functions.
- **Frame timing.** Hookshot runs at its own speed (30 to 60 fps, a high-fps option). The co-op sampler and puppets work from time, not frames; to check with a puppet in view.
- **Addresses.** Code offsets are checked (`set_time`); the data slots are read through the same `CoopGameBuild` offsets from main's base, and the first runs check them (the scene and Link read, puppets made).
- **The co-op window.** The emulator's Qt window is not on Hookshot; the chat, name tags, player list, panel, HUD and cheats are drawn in Hookshot's ImGui frame instead ("Where the co-op module lives" above).
- **Licences.** Hookshot is GPL-3.0, as we are. Its lifted C contains the game and is never shared; we ship our module, our patch and our scripts, and each player builds Hookshot from their own game.

## Emulator and Hookshot players together
